# The text-to-speech service on 192.168.1.162 — two builds, one host

Measured 2026-10-01 (s090). Host `192.168.1.162` runs **two different builds of the same
service** side by side, and they are **not interchangeable configuration-wise**.

| | `:8880` (old) | `:8881` (new) |
|---|---|---|
| `GET /v1/audio/voices` | 322 Azure voices + 23 aliases | **exactly one** voice: `canto-tts-nano-v1` (zh-HK), **17 aliases** |
| `cantonese` | 200 (alias → `zh-HK-HiuMaanNeural`) | **200** (alias → `canto-tts-nano-v1`) |
| `zh-HK-HiuMaanNeural` | 200 | **400** |
| `canto-tts-nano-v1` | **400** | 200 |
| `nova` | 200 | 200 |
| bad voice | 400, body names `GET /v1/audio/voices?locale=zh-HK` | 400, body says *"canto-tts publishes exactly one voice … did you mean: ['nova']? GET /v1/audio/voices"* |
| empty input | 422 | 422 |
| audio | `MPEG ADTS layer III v2, 48 kbps, 24 kHz mono`, **no ID3 tag** | `MPEG ADTS layer III v2, 64 kbps, 24 kHz mono`, **ID3v2.4 tag** |
| 30-word line | 70,992 B / 7.02 s | 65,901 B / **3.78 s** |
| short line | 14,832 B / 1.03 s | 19,821 B / 0.95 s |

Both are Azure-Speech-*compatible in shape* (`POST /v1/audio/speech`, `{input, voice}` → `audio/mpeg`),
which is all the fork's server requires. The difference is what is behind it: **8880 proxies Azure's
catalogue; 8881 bakes one Cantonese voice** and answers every one of its aliases itself.

## What this means for the fork

- **Moving the host is a one-line config change** (`commentary.speech.host` in
  `~/.config/opencode/opencode.jsonc`). **The voice does not have to change** — `cantonese` is an
  alias on both ports, so the shipped `voice: "cantonese"` keeps working. Anything set to a full
  Azure name (`zh-HK-HiuMaanNeural`, `alloy`, `en-US-*`, …) would **stop working** on 8881 and
  every line would come back text-only.
- **A bad voice degrades, it does not break.** `SessionCommentary.append` publishes the line first
  and forks the audio render; a failure is logged as `commentary audio render failed`
  (`commentary.ts:690-695`) and the row simply has no `audio` hash. The reader gets the text.
- **The hashes are per (voice, text)**, so switching host invalidates nothing that is already
  stored — the file name is `sha256(voice + "\n" + text)`, and both ports answer to `cantonese`.
  Old files stay valid; new lines get a different bitrate.

## Where the fork's config now stands (2026-10-01, s090 part 2)

`~/.config/opencode/opencode.jsonc`:

```jsonc
"commentary": {
  "speech": {
    "host": "192.168.1.162:8880",                                  // the default; unchanged
    "hosts": ["192.168.1.162:8880", "192.168.1.162:8881"],          // what the voice picker offers
    "voice": "cantonese"                                            // an alias on BOTH ports
  }
}
```

`host` is deliberately still `:8880`: it is what a browser that has never opened the picker renders
with, and `:8880` answered throughout while `:8881` was refusing connections. The picker sends the
`(host, voice)` **pair** on the commentary lease, so choosing the `:8881` voice switches the endpoint
for that browser without a config edit (DEC-061). Backup of the file before the edit:
`/tmp/opencode/opencode.jsonc.bak-s090`.

## Operational note (measured, not assumed)

`:8881` was **actively refusing connections** for at least 90 s when first probed (instant
`http=000`, 1.6–12 ms — refused, not dropped; the host pinged at 15 ms throughout), and came up
**~40 s** into a 2-minute poll. The service is being restarted in place, so **"connection refused"
here means "still starting", not "wrong port"** — poll before concluding anything. `:8880`
answered normally throughout, which is the argument for keeping the old port configured until the
new one has been watched for a while.
