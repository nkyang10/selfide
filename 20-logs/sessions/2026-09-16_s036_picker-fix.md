# Session s036 — fix folder picker: empty tree on open + dead chevron + scroll-to-top

- **Date:** 2026-09-16 (UTC)
- **Branch:** `dev` (p003-opencode-fork)
- **Why:** user forwarded the latest on-device report — picker tree empty on first open, plus the
  earlier symptoms (chevron click dead / reload+scroll-to-top). Working from the reverted clean
  `375cff8`-equivalent picker base with the `be03932` instrumentation build deployed on :4447.
  The local `dev` branch had been reset to `origin/dev` (`reflog: reset: moving to origin/dev`),
  so the working tree was the clean 375cff8 picker with NO `[picker-tree]` logs while the live
  build (PID 2705601) still had them.

## Result

### Root causes (all confirmed in code + verified live)
1. **Empty tree on open.** `directory-tree-zag.tsx` at 375cff8 never adopted loaded children back
   into the controlled collection: `machineProps` had `loadChildren` but **no**
   `onLoadChildrenComplete`/`onLoadChildrenError`, so `setCollection(details.collection)` never ran.
   Combined with the auto-expand effect `createEffect(on(collection, …), { defer: true })`: the
   deferred first run consumed the initial `setCollection(buildCollection())` (fired by the earlier
   `on(props.root)` effect, which runs before it in effect-creation order), so the `expand([ROOT_VALUE])`
   callback never fired → root never expanded → no children → `getVisibleNodes()` stays 0.
2. **Dead chevron / expand not working.** The 375cff8 row rendered `<button {...getBranchProps()}>`.
   In Zag tree-view 1.43 `getBranchProps` is the `role="treeitem"` row wrapper with **no click
   handler** (verified in `tree-view.connect.mjs`). The expand/select handlers live on
   `getBranchControlProps` (click → `BRANCH_NODE.CLICK` → select+expand with `expandOnClick:true`)
   and `getBranchTriggerProps` (click → `BRANCH_TOGGLE.CLICK`). So no DOM click could ever expand a
   folder. (Also `getRootProps()` on the tree container instead of `getTreeProps()`, and leaf rows
   rendered `fallback={null}`.)
3. **Scroll-to-top.** `visible()` memo returned fresh `{node,indexPath}` objects from
   `getVisibleNodes()` after every adopted child-load; Solid `<For>` keys rows by item **reference
   identity**, so every collection adoption unmounted+remounted all rows → `.directory-picker-v2-browser`
   (overflow:auto) reset to top.

### Fix (committed + pushed: fork `dev` `939a0e6`, 2026-09-16)
- `packages/app/src/components/directory-tree-zag.tsx`
  - Add `onLoadChildrenComplete: (details) => setCollection(details.collection)` +
    `onLoadChildrenError` (noop) to `machineProps`.
  - Auto-expand effect: key on `[props.root, collection]`, `defer: false` — fires on mount and on
    every root/collection change so ROOT_VALUE expands reliably (the old `defer:true`-on-collection
    consumed its only trigger). `expand()` is idempotent so re-fires are harmless.
  - Row DOM restructured to canonical Zag 1.43 anatomy: treeitem = `getBranchProps`, click/select
    control = `getBranchControlProps`, chevron `<button type="button">` = `getBranchTriggerProps`,
    label = `getBranchTextProps`; leaf rows now render `getItemProps` + `getItemTextProps` (were
    `fallback={null}`). Container uses `getTreeProps()` (keyboard nav + role=tree).
  - Stable-keyed `visible()` memo: reuse one cache object per `node.value` across recomputations
    (updated in place, pruned when no longer visible) so `<For>` reference-keying keeps existing rows
    mounted → no remount → no scroll reset on expand.
- `packages/app/src/components/dialog-select-directory-v2.css` — row rules rewritten to target Zag
  `data-part` attributes (`branch`, `branch-control`, `branch-trigger`, `branch-text`, `item`,
  `item-text`) instead of the old `[role=treeitem]`/`button` catch-alls (which made the chevron
  button full-width and broke the new nested structure).
