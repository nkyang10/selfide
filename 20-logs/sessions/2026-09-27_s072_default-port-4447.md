## What the user asked for

Make **4447** the port the fork listens on **by default after install** — i.e. a plain `opencode web` /
`opencode serve` with no `--port` should serve on `:4447` instead of upstream's `:4096`. Today every deploy in
this project has to pass the port explicitly (`scripts/run-web.sh 4447` → `web --port 4447`); after this change
the default matches the port the fork is already known by.

## Where the default actually lives (traced before editing)

There is **no** `default: 4447` in the CLI. The chain is:

1. `packages/opencode/src/cli/network.ts:6-11` — the yargs `port` option defaults to **`0`** (meaning "no
   preference"); `--port` on the command line, else `config.server.port` from `opencode.json`, else that `0`
   (`resolveNetworkOptionsNoConfig`, :62-79).
2. `packages/opencode/src/server/server.ts:117-122` `startWithPortFallback` — **this is the real default**:
   `port !== 0` → listen there; `port === 0` → try the preferred port, and on failure fall back to *any free
   port*. That preferred port was hard-coded **4096**.
3. `packages/opencode/src/cli/cmd/web.ts:54,64,73` and `serve.ts:20` print `server.port`, i.e. whatever the
   listener actually got — no port literal, nothing to change.

So one line is the whole behavioural change, and it covers **both** `web` and `serve` (and the TUI, which spawns
a server through the same path). `server.port` in `opencode.json` and an explicit `--port` still win, unchanged.
